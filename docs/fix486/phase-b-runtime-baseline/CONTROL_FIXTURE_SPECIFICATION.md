# FIX486B runtime control fixture

## Purpose

This fixture proves that a clean packaged AstraVector runtime can execute the production ingestion and retrieval path. It is not a retrieval-quality bank and must not be merged into the frozen FIX486 bank without explicit Phase C work.

## Logical identity

```text
fixture_id=fix486b-runtime-control-v1
access_zone_label=FIX486B_BASELINE_ZONE
document_label=fix486b-runtime-control
document_version=1
lifecycle=ACTIVE
language=en
```

Physical UUIDs must be generated by production identity logic and captured after ingestion. Do not hardcode physical UUIDs in the fixture.

## Content requirements

The source must produce:

```text
one SOURCE
at least one PARENT
at least one SUB_180 or SUB_260
```

Required exact anchor:

```text
ASTRA_FIX486B_RUNTIME_CONTROL
```

Required semantic statement:

```text
PostgreSQL is the canonical state and Qdrant is a search projection.
```

The parent must contain enough context that `parent_text` is non-empty and differs meaningfully from a precise child hit.

## Production-path rules

- Ingest through the public production ingestion facade or its exact production service path.
- Use the configured production chunker, tokenizer and inference engine.
- Do not insert chunks, embeddings, bindings or Qdrant points directly.
- SQL may be used only for read-only audit after ingestion.
- Record request ID, document identity, returned chunk identities and Qdrant binding identities.

## Idempotency probe

Execute the same logical request with the same idempotency identity twice.

Required assertions:

```text
new documents after second request = 0
new chunks after second request = 0
new bindings after second request = 0
new outbox effects after second request = 0
```

## Search probe

Query:

```text
ASTRA_FIX486B_RUNTIME_CONTROL canonical state
```

Required minimum assertions:

```text
expected document returned
version = 1
matched_chunk_id present
parent_chunk_id present
matched_text non-empty
parent_text non-empty
wrong-zone results = 0
wrong-version results = 0
```

## RetrieveContext probe

Use the same query and equivalent filters through the public retrieval facade.

Required minimum assertions:

```text
context count >= 1
logical document/version identity matches Search
matched child identity matches the selected Search result or is explicitly explained by deterministic facade mapping
parent identity and parent text are non-empty
citation/source metadata are present where the production contract requires them
```

## Restart probe

After successful ingestion:

1. stop only the AstraVector runtime;
2. leave PostgreSQL and Qdrant data intact;
3. restart the same release binary with the same resolved config;
4. rerun Search and RetrieveContext without reingestion;
5. compare normalized logical results.

## Evidence

Persist a compact `control-fixture-identity.json` containing:

```text
fixture SHA-256
request identity
zone identity
document ID/version
SOURCE/PARENT/child physical IDs
binding/point IDs
content hashes
Search logical result identity
RetrieveContext logical result identity
```

Volatile timestamps and process IDs must not be treated as deterministic fixture identity.
